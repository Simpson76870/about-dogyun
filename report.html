과제 5 · 대화가 끊겨도 이어지는 프로젝트

비교 보고서 — 같은 개선 하나를 두 AI 세션이 차례로 이어서 완성했고, 새 세션은 저장소와 인수인계 문서만으로 같은 검사 10개를 모두 통과시켰습니다.

개선 기능: 환율 정보판의 “마지막 갱신 시각 표시 + 오래된 데이터 경고” (과제 4) · 공통 상한: 작업 90분, 요청 25회 · 소스: github.com/Simpson76870/about-dogyun

4. 인수인계 문서

X가 남긴 fx-board/handoff/HANDOFF.md (일곱 항목: 목표 / 현재 상태 / 실행 명령 / 통과 검사 / 남은 문제 / 다음 행동 / 건드리지 말 것). 현재 상태에 코드 기준 커밋과 첫 실패 검사(T-06)를 적었습니다.

  • Y에게 준 것: 저장소 주소와 이 문서뿐이며, 앞 대화나 추가 자료는 주지 않았습니다.
  • 인수인계 누락: 기록된 것 없음. Y가 시작한 뒤 이 문서를 고친 커밋이 없습니다(문서 커밋 #5·#6은 모두 Y 시작 전).
  • 새 환경 재현: 실행 명령은 Actions가 매번 새 서버에서 처음부터 설치하고 실행하는 방식으로 재현됩니다(#2~#8).

5. 다음 작업에서 도구를 고르는 내 기준

같은 검사를 자동으로 돌릴 수 있는 작업은 인수인계 문서를 먼저 쓰고, 요청 수가 적게 든 쪽에 이어서 맡긴다.

한계: 한 번만 해 본 비교이고, X는 구조·검사 설계를 이어받은 기능 구현까지, Y는 남은 4개 검사만 맡아서 일의 양이 같지 않았습니다. 그래서 시간·요청 수의 차이는 도구의 우열이 아니라 맡은 몫의 차이일 수 있습니다.

6. 짧은 확인 방법 4줄

  1. 위치: github.com/Simpson76870/about-dogyun/actions 의 handoff-checks
  2. 3단계 이내 행동: ① 목록 맨 위 실행(#8, “Fix timestamp validation…”)을 연다 → ② checks를 누른다 → ③ Run 10 frozen checks를 펼친다.
  3. 통과 모습: PASS가 T-01~T-10까지 열 줄 보이고 마지막 줄이 10/10 PASS. 바로 위 Verify frozen checks도 초록 체크.
  4. 안 될 때 모습: 실행 줄이 빨간 ✗이고 로그에 FAIL T-0x … 줄이 남습니다. 로그가 열리지 않으면 아래 7번의 결과 사본으로 대신 확인하세요.

7. AI와 나의 판단 3줄

  1. AI에게 맡긴 일: 검사 10개·사용 상한·화면 계약 초안 설계, 환율 정보판 기능 구현과 인수인계 문서 작성(X), 문서만 받고 남은 검사 4개를 구현(Y).
  2. 직접 판단한 일: 개선 대상(과제 4 환율 정보판의 갱신 시각·오래된 데이터 경고)과 두 AI의 역할 분담, Y를 다른 서비스로 정하기, 로컬 설치 대신 GitHub Actions로 검사하기, 문서의 커밋 번호를 저장소와 대조한 뒤에야 Y를 시작하기, Y에게 문서 외 자료를 주지 않기, 결과를 Actions 화면에서 직접 확인하기.
  3. AI 제안을 따르지 않은 일: 새 채팅에서 X를 시작하자는 제안 대신 준비 과정이 쌓인 같은 대화를 X로 쓰기로 했고(요청 수는 X 시작 이후만 셈), 내 컴퓨터에 검사 도구를 설치하자는 제안도 따르지 않고 GitHub Actions로 바꿨습니다.
