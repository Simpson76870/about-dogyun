코드 표기 변화에 따른 규칙 기반 취약점 탐지의 안정성

Python 코드의 의미는 같아도 import 별칭을 바꾸면 취약점 탐지 결과가 달라질까?

2026년 10월 26일 · 공개 연구 요약 및 본문

초록

연구자가 구성한 Python 취약 사례 12개와 정상 맥락 사례 10개에 대해 AST 기반 규칙 검사기의 탐지 특성을 분석하고, 6개 취약 사례의 import 별칭 변형에 대한 안정성을 평가하였다. 원본 취약 사례 12/12개에서 경고가 발생한 반면 정상 맥락 사례에서는 5/10개에 경고가 발생했다. 원본에서 탐지된 7개 항목 중 별칭 변형 후 유지된 항목은 1개였다. 이는 표면적인 코드 표기 방식에 대한 규칙의 의존성을 보여준다. 본 연구는 사후 탐색적 사례연구로서 AI의 반복 검토 효과를 입증하지 않는다.

1. 연구 배경 및 질문

원래 과제의 질문은 “동일 코드를 AI가 연속해서 두 번 검토하면 2차 검토에서 새로운 실제 취약점을 발견하는가?”였다. 그러나 독립된 블라인드 AI 검토 24회가 수행되지 않았으므로 해당 가설의 실증 결론은 보류한다.

보조 연구 질문: 동일한 의미의 Python 코드에서 import 별칭만 바꾸었을 때, 원본에 맞춰 조정된 규칙 기반 취약점 탐지기의 발견 결과는 유지되는가?

2. 연구 설계 및 측정

연구자가 구성한 취약 예제 S01–S12와 참조 발견 14건을 사용했다. 정상 맥락 예제 10개에 동일 검사기를 적용하고, 6개 취약 예제에 의미를 보존하는 import 별칭 변형을 적용했다. 원본 예제에 맞춰 검사기를 조정했으므로 독립된 테스트 세트가 아니다.

사례 단위 민감도는 경고된 취약 사례/전체 취약 사례, 특이도는 경고 없는 정상 사례/전체 정상 사례, 정확도는 올바르게 분류된 사례/전체 사례, 발견 유지율은 변형 후에도 탐지된 기존 발견/변형 전 기존 발견으로 계산했다.

3. 관측 결과

100%취약 사례 탐지 · 12/12
50%정상 사례 특이도 · 5/10
77.3%전체 사례 정확도 · 17/22
14.3%별칭 변형 탐지 유지 · 1/7

원본 취약점 참조 발견 14건에 대한 규칙 탐지 14/14와 사례 단위 민감도 12/12는 분모가 다르다. 별칭 변형 사례 6개 모두에서 최소 1개 발견이 소실되었다.

Wilson 95% 구간은 민감도 약 75.8–100%, 특이도 약 23.7–76.3%, 전체 정확도 약 56.6–89.9%, 별칭 발견 유지율 약 2.6–51.3%이다. 비무작위 표본 및 사례 내 의존성 때문에 모집단에 대한 확률적 보증으로 해석하지 않는다.

4. 민감도 분석과 해석

정상 사례에서 발생한 경고 5건은 사용 맥락에 따라 실제 보안 위험으로 재분류될 수 있다. 정답 판정이 달라진다는 가정하에 특이도는 달라지며, 기존 50%를 확정적 오탐률로 간주할 수 없다. 별칭 변형에서 7개 중 6개 발견이 사라진 사실은 이 검사기의 표기 민감성을 보여주지만 전체 정적 분석 도구의 일반 성능을 뜻하지 않는다.

5. AI 반복 검토 기록의 위치

현재 대화에서 작성된 1차·2차 검토 기록은 총 24개이며, 1차 참조 발견 14건 및 2차 신규 발견 0건으로 사후 채점되었다. 그러나 작성자가 참조 정답에 노출되었고 동일한 대화 맥락을 공유하므로 블라인드 독립 AI 실험이 아니다.

독립 AI 검토 실행은 0/24건이다. 원래 가설에 대한 효과 추정이나 유의성 검정에 이 기록을 사용하지 않는다.

6. 연구 한계 및 결론

사례가 소규모이고 연구자에 의해 선택되었으며 규칙이 원본 예제에 맞춰져 있어 선택·조정 편향이 크다. 정상 사용 맥락에 대한 외부 판정자가 없고 별칭 변형은 한 종류의 의미 보존 변화만 포함한다.

그럼에도 동일 검사기가 원본 사례에서는 높은 탐지율을 보이면서 별칭 변형에서는 다수의 탐지를 잃었다는 관측은 재현 가능하다. 결론은 이 제한된 사례군에만 적용되며 AI 반복 검토의 효과는 미검증으로 남는다.

7. 재현 자료와 연구 윤리

코드 사례, static_baseline.py, negative_control_test.py, alias_robustness_test.py, 정량 분석 스크립트, CSV·JSON 결과 및 REPRODUCE.md로 결과를 확인할 수 있다. 합성 검증 데이터나 사후 기록을 독립 실험으로 표기하지 않는다.
